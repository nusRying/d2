# ADR 003: Deterministic Go RNG Parity

## Status
Accepted

## Reference
- **D2 base:** `01bc7ecdbdd04c13d6fe5df1967d2d9aa14ae579`
- **Go reference:** `go1.27.0`
- **Go source:** `src/math/rand/rng.go`, `src/math/rand/rand.go`

## Required APIs
`Int63`, `Int63n`, `Float64`

## Decision
Exact Go sequence parity was chosen to preserve perfect determinism. The exact stream of random numbers generated by Go's `math/rand` must be replicated to ensure TALA layouts are identical across both languages.

## Integer representation
JavaScript `BigInt` is necessary because JavaScript `Number` represents all numbers as IEEE-754 double-precision floats, which lose precision for integers beyond `2^53 - 1`. Go's `math/rand` LFSR generator and rejection sampling logic rely on precise 64-bit integer overflow math (`int64` and `uint64`), which cannot be safely emulated with `Number`.

## Seed contract
- **BigInt**: Must fit within the signed `int64` bounds.
- **Number**: Must satisfy `Number.isSafeInteger()` and fall within the signed-int64 range.

## Float parity
`Float64` outputs are compared using their exact IEEE-754 bit patterns against the Go oracle to guarantee zero precision loss across the language boundary.

## Rejection sampling
Explicit proof of rejection sampling execution was verified against the oracle:
- **seed:** `1`
- **bound:** `4611686018427387905`
- **source draws:** `4`

## Independent streams
Go TALA creates separate RNG pipelines for different steps (in `pipeline.go`):
- `hierarchyPlacementRandom: rand.New(rand.NewSource(seed))`
- `random: rand.New(rand.NewSource(seed))`

Therefore, JS must create separate RNG instances rather than using shared/global state to maintain correct independent stream states.

## Alternatives considered
- **Math.random()**: Rejected because it is not seedable and the implementation is engine-specific.
- **Third-party seeded PRNG**: Rejected because standard PRNGs do not match Go's specific lagged Fibonacci sequence and internal `seedrand` warmup.
- **Number-only 64-bit arithmetic**: Rejected because simulating 64-bit math via 32-bit chunking in JS is error-prone and verbose.
- **Statistical-equivalence-only testing**: Rejected because TALA requires exact sequence replication, not merely a uniform distribution.
